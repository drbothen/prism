# S-5.04-FIX-001 — .factory: Fix S-5.04 depends_on (S-2.07 superseded by ADR-023)

**Status:** draft
**Version:** v1.1

---

## Origin

E2E-DEMO-WIRING-PLAN.md §1 (j) identified that S-5.04's `depends_on: [S-5.03, S-2.07]`
is broken: S-2.07 was merged with patterns that are now superseded by ADR-023
(PLUGIN-MIGRATION-001-H merged 2026-05-27). The S-2.07 per-sensor auth pattern is retired;
S-5.04's health checks must use `SpecDrivenSensorAdapter` via the `AdapterRegistry` populated
by S-DEMO-001. The depends_on must be updated before S-5.04 is dispatched to the implementer.

---

## Narrative

As the factory-artifacts record, I want S-5.04's `depends_on` to reflect the current
architectural reality (ADR-023 plugin migration supersedes S-2.07), so that the sensor
health subsystem implementer receives correct prerequisite guidance and can build health
checks against live `SpecDrivenSensorAdapter` instances rather than against the retired
S-2.07 per-sensor auth pattern.

---

## Authority

BC-2.08.001 (On-Demand Connectivity Check Per Sensor Per Client) in frontmatter is the
primary authority for the acceptance criteria in this story.

ADR-023 is the authoritative architecture document that superseded the S-2.07 per-sensor
auth pattern. Read it before reviewing this story:
`.factory/specs/architecture/decisions/ADR-023-plugin-only-sensor-architecture.md`.

ADR-023 §Decision Rules establishes `SpecDrivenSensorAdapter` via `AdapterRegistry` as
the canonical sensor access pattern. S-2.07 introduced per-sensor auth modules that are
retired under this mandate — this fix story exists to correct S-5.04's `depends_on` to
reflect that architectural reality. ADR-023 is partially amended by ADR-054 (standard
HTTP token-acquisition now native declarative), but is NOT superseded; §Decision Rules
remains load-bearing.
