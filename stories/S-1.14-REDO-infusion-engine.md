## Narrative

As the Prism query engine, I want the infusion enrichment framework fully implemented —
loading `.infusion.toml` fixtures via `InfusionLoader`, maintaining a live `InfusionRegistry`
with arc-swap hot reload, registering enrichment sources as DataFusion UDFs in a
`SessionContext`, executing `| enrich type=...` pipe stages per query, deduplicating
enrichment calls via a per-query cache, and persisting enrichment results in the RocksDB
`infusion_cache` column family — so that analysts can enrich query results with GeoIP,
threat intelligence, and asset inventory context using the `| enrich` pipe stage.

## Tasks

1. Implement `InfusionLoader::parse` at `loader.rs:42`:
   - Read `*.infusion.toml` from `{config_dir}/infusions/` directory.
   - Deserialize using `toml` crate into `InfusionSpec`.
   - Validate: `infusion_id` present, at least one `[[infusion.fields]]` entry, `source.type`
     is one of `maxmind_mmdb | csv | json_lookup | plugin`.
   - Validate credential references use reference-based model (no inline values per AD-017).
   - Validate `pipe_stage.adds_columns` is a non-empty subset of `[[infusion.fields]]` names
     (validated by `InfusionLoader::validate_pipe_stage_columns`). A pipe stage may project a
     strict subset of infusion fields — this is correct behavior for selective `| enrich` projection.
   - On any validation error: return `Err(SpecEngineError::InfusionValidation(...))`.
   - **Duplicate `infusion_id` loader semantic (BC-2.19.001 v2.1 postcondition):** When
     `InfusionRegistry::load_spec` or `load_spec_with_runtime` is called with an `infusion_id`
     that is already registered, the new spec REPLACES the prior entry (last-writer-wins). Before
     inserting the new spec's UDF names into `udf_to_infusion`, the implementation MUST purge ALL
     stale reverse-index entries that belonged to the OLD spec's fields. Failure to purge creates
     dangling entries where `is_api_backed()` returns incorrect results. This mirrors the purge
     logic already applied in `hot_reload`; apply it identically in `load_spec`/`load_spec_with_runtime`.

2. Implement `InfusionLoader::load_all` at `loader.rs:50`:
   - Call `parse` for each `.infusion.toml` found in the directory.
   - For each valid spec: construct the appropriate `InfusionSource` impl:
     - `source.type = "maxmind_mmdb"` → `MmdbSource::load(path)`
     - `source.type = "csv"` → `CsvSource::load(path, key_column)`
     - `source.type = "json_lookup"` → `JsonLookupSource::load(path)`
     - `source.type = "plugin"` → `PluginInfusionSource` (delegates to S-1.15 WASM)
   - **Source file size guard (SEC-001 / CWE-400 hardening, BC-2.19.001 v2.1 E-INFUSE-012):**
     Before reading any file-backed source (CSV, JSON whole-file, MMDB metadata), stat the file
     and check its size against `MAX_SOURCE_FILE_BYTES` (100 MiB = 104_857_600 bytes). If the
     file exceeds this limit, return `Err(InfusionError::SourceFileTooLarge { path, size, limit })`
     which maps to error code `E-INFUSE-012`. This guard applies to:
     - `CsvSource::load(path, ...)` — check before opening
     - `JsonLookupSource::load(path)` — check before reading
     - `MmdbSource::load(path, ...)` — check before `Reader::open_readfile()`
     The check must also fire on hot reload (when `InfusionRegistry` reloads a spec from disk).
     A file that is within the limit at boot may grow beyond it before a reload; the guard
     must be re-evaluated every time a source file is opened.
   - Return `InfusionRegistry` with all loaded specs + sources.

3. Implement `InfusionLoader::validate_credentials` at `loader.rs:57/66`:
   - For each `InfusionSpec` with `[infusion.credentials]` entries, perform a STRUCTURAL
     check: verify the credential reference is non-empty (ref name / env_var present in
     the TOML) and syntactically valid. This is a parse-time structural check ONLY.
   - Credentials are resolved at source-call time per AD-017 (the per-query execution path),
     NOT at load time. `validate_credentials` MUST NOT attempt to look up the actual
     credential value in `CredentialStore` or resolve env vars — those operations happen
     in `InfusionSource::enrich_single` and `HttpLookupSource::enrich_single` when a query
     runs. Remove or soften any "verify refs resolve in CredentialStore" language — that
     interpretation is incorrect and would introduce a boot-time `CredentialStore`
     dependency that does not match the AD-017 model.
   - If structural validation fails (e.g., empty ref name or empty env_var): return `Err`
     with the ref name but NOT any credential value.
   - Per BC-2.19.005: credential values must never appear in errors or logs.

4. Implement `MmdbSource::load/enrich_single/enrich_batch` at `sources/mmdb.rs:23/29/37`.
   The existing stub has a WRONG return type: `Result<Self, crate::infusion::loader::InfusionLoader>`
   must be changed to `Result<Self, prism_core::InfusionError>`.
   The `maxminddb = "0.28"` API uses a `LookupResult` lazy-decoding wrapper (NOT bare `T`):
   ```rust
   pub struct MmdbSource {
       reader: maxminddb::Reader<Vec<u8>>,
       field_names: Vec<String>,  // declared output fields from spec
   }
   impl MmdbSource {
       /// Load a MaxMind MMDB file (maxminddb 0.28).
       /// Return type MUST be Result<Self, prism_core::InfusionError> (not InfusionLoader).
       pub fn load(path: &std::path::Path, field_names: Vec<String>) -> Result<Self, prism_core::InfusionError> {
           let reader = maxminddb::Reader::open_readfile(path)
               .map_err(|e| prism_core::InfusionError::MissingRequiredField {
                   field: format!("mmdb_open_failed: {}", e),
                   spec_path: path.to_string_lossy().to_string(),
               })?;
           Ok(Self { reader, field_names })
       }
       pub fn enrich_single(&self, ip: &str, _input_type: &str) -> Option<serde_json::Value> {
           let addr: std::net::IpAddr = ip.parse().ok()?;
           // maxminddb 0.28: lookup() returns Result<LookupResult<'_, T>, MaxMindDbError>
           // LookupResult must be deserialized — it does NOT auto-coerce to T.
           let lookup = self.reader.lookup::<serde_json::Value>(addr).ok()?;
           // In maxminddb 0.28, LookupResult<T> implements Deref<Target=T> (or is a direct T).
           // Confirm via docs whether `.deserialize()` or dereferencing is needed.
           // Use the approach that compiles against 0.28 — test with `just iter prism-spec-engine`.
           Some(lookup)
       }
       pub fn enrich_batch(&self, ips: &[String], input_type: &str) -> Vec<Option<serde_json::Value>> {
           ips.iter().map(|ip| self.enrich_single(ip, input_type)).collect()
       }
   }
   ```
   **IMPORTANT:** Verify the exact `LookupResult` deserialization pattern against maxminddb 0.28
   docs before implementing. The pattern above is approximate. Run `just iter prism-spec-engine`
   to confirm compilation.

6. Implement `InfusionLruCache::get/insert` at `cache.rs:129/140`. The existing struct
   uses `_inner` (underscore = unused field). Rename `_inner` to `inner` when implementing.
   Use the existing `LruCacheEntry` struct (with `value: Value` + `expiry_unix_secs: u64`).
   In lru 0.17, `LruCache::put(key, value)` is the insert method (confirmed correct API):
   ```rust
   impl InfusionLruCache {
       /// Look up by composite key "{infusion_id}:{input_value}". Lazy TTL eviction.
       pub async fn get(&self, infusion_id: &str, input_value: &str) -> Option<serde_json::Value> {
           let key = format!("{}:{}", infusion_id, input_value);
           let mut cache = self.inner.lock().await;
           if let Some(entry) = cache.get(&key) {
               let now = std::time::SystemTime::now()
                   .duration_since(std::time::UNIX_EPOCH)
                   .unwrap_or_default()
                   .as_secs();
               if entry.expiry_unix_secs > now {
                   return Some(entry.value.clone());
               }
               // Expired — lazy eviction
               cache.pop(&key);
           }
           None
       }
       /// Insert with TTL. `ttl_secs` from `infusion_spec.cache_ttl_secs` (default 3600).
       pub async fn insert(&self, infusion_id: &str, input_value: &str, value: serde_json::Value, ttl_secs: u64) {
           let key = format!("{}:{}", infusion_id, input_value);
           let expiry_unix_secs = std::time::SystemTime::now()
               .duration_since(std::time::UNIX_EPOCH)
               .unwrap_or_default()
               .as_secs()
               .saturating_add(ttl_secs);
           self.inner.lock().await.put(key, LruCacheEntry { value, expiry_unix_secs });
       }
   }
   ```
   Note: the stub's `get/insert` method signatures use `(key: &str)` but the struct needs
   `(infusion_id, input_value)` for consistent key format with `QueryScopedInfusionCache`.
   Update the public signature — the `infusion_id + input_value` form is already used in
   `QueryScopedInfusionCache::get/insert` and must be consistent.

7. Implement `QueryScopedInfusionCache` (Tier 1 per-batch dedup):
   ```rust
   pub struct QueryScopedInfusionCache {
       map: HashMap<String, Option<serde_json::Value>>,  // key = "{infusion_id}:{input_value}"
   }
   ```
   Tier-1 `QueryScopedInfusionCache` is allocated fresh per DataFusion batch (in

## Acceptance Criteria

**AC-1:** Given `geoip.infusion.toml` with `type = "local_lookup"` and `source.type = "maxmind_mmdb"`,
When `InfusionLoader::load_all` runs, Then `geoip_country`, `geoip_city`, `geoip_asn`, and
`geoip_is_tor` are exported as `InfusionUdfDescriptor` entries from `InfusionRegistry`.
(traces to BC-2.19.001 postcondition — each field registers exactly one UDF descriptor)

**AC-2:** Given a query `SELECT geoip_country(device_ip) FROM EVENTS` executed against a result
set with 500 events having 30 unique IPs, When the query executes with the per-query dedup cache
active, Then `MmdbSource::enrich_single` is called exactly 30 times (not 500 times).
(traces to BC-2.19.002 postcondition — unique input values only)

**AC-3:** Given `geoip.infusion.toml` loaded into `InfusionRegistry` (4 `[[infusion.fields]]` entries:
`geoip_country`, `geoip_city`, `geoip_asn`, `geoip_is_tor`; no `[infusion.pipe_stage]` declared),
When `InfusionRegistry::enrich_descriptor("geoip")` is called, Then the returned `EnrichStageDescriptor`
has:
- `infusion_name = "geoip"` — the registry lookup key passed to `enrich_descriptor()`, which EQUALS
  `infusion_id` (NOT the human-readable `spec.name` field); this identity is required by
  BC-2.19.001 v2.1 (A2)
- `input_field = "device_ip"` (the join key from the spec's first `[[infusion.fields]]` entry)
- `output_columns = ["geoip_country","geoip_city","geoip_asn","geoip_is_tor"]` in declaration order
  — when no `pipe_stage` is declared, all field names in declaration order (BC-2.19.001 v2.1 A1)
- `infusion_id = "geoip"`

When the same spec is loaded WITH `[infusion.pipe_stage] adds_columns = ["geoip_country","geoip_city"]`,
Then `output_columns = ["geoip_country","geoip_city"]` (the `adds_columns` validated subset, in declared
order) — `geoip_asn` and `geoip_is_tor` are excluded. A pipe stage may project a strict subset.

Additionally, the SQL-mode UDF `SELECT geoip_country(device_ip) FROM EVENTS` resolves enrichment
columns via the registered DataFusion `ScalarUDF` (wired per Task 9 / Task 10).
**Scope note:** pipe-mode `| enrich geoip ON device_ip` RUNTIME execution (RecordBatch hydration
via `Ast::Pipe` materialization) is SCOPE-DEFERRED to S-3.01 per architect ruling S-1.14-REDO Q1
(2026-06-18). AC-3 is satisfied when `enrich_descriptor()` returns the correct descriptor and the
SQL-mode UDF path is wired — not when the pipe-mode runtime is operational.
(traces to BC-2.19.001 v2.1 postcondition — enrich_descriptor() returns well-formed EnrichStageDescriptor;
output_columns source-of-truth per A1; infusion_name identity per A2; SQL-mode UDF path wired;
scope boundary clause anchors pipe-mode deferral to S-3.01)

**AC-4:** Given an infusion `threat_intel` with `type = "plugin"`, When a detection rule
references `threat_score(device_ip)` in its `filter` expression, Then `is_api_backed("threat_score")`
returns `true` and the detection rule loader rejects with `E-RULE-012`.
(traces to BC-2.19.003 postcondition — API-backed UDFs rejected in detection rules)

**AC-5:** Given a valid infusion spec loaded, When the `.infusion.toml` file is modified and
the file watcher fires (via S-1.12-FOLLOWUP), Then the `InfusionRegistry` is updated atomically
and in-flight queries using the old registry complete without error.
(traces to BC-2.19.004 postcondition — hot reload atomicity, CI-002 invariant)

**AC-6:** Given an infusion spec with `[infusion.credentials]` entries, When the loader returns
an error, Then no credential values appear in any log output or error message (only ref names).
(traces to BC-2.19.005 postcondition — credential redaction)

**AC-7:** Given an infusion result fetched from a live source, When it is stored in RocksDB
`infusion_cache` CF, Then a subsequent query (after Tier 1 and Tier 2 LRU have expired) reads
from RocksDB without calling the live source again.
(traces to BC-2.19.002 postcondition — three-tier cache reduces live source calls)

**AC-8:** VP-049 proptest passes: for any input sequence of N values with K distinct (K <= N),
`enrich_single` is called exactly K times.
(traces to BC-2.19.002 postcondition)

**AC-9:** No `unimplemented!()` or `todo!()` may remain in `loader.rs`, `cache.rs`,
`sources/mmdb.rs`, `sources/csv.rs`, `sources/json_lookup.rs` before merge.
`plugin_bridge.rs` may contain a single annotated `todo!("S-1.15 — WASM runtime required")`
if S-1.15 is not yet merged. Per POL-12.
(traces to BC-2.19.001 invariant — no incomplete source type stubs in production module)

**AC-10 (hollow-feature wiring — lesson z24):** Given a production `prism start` boot with
a `{config_dir}/infusions/` directory containing at least one `.infusion.toml` file,
When `boot.rs` completes boot step N (infusion loading), Then `InfusionLoader::load_all()`
is called, the resulting `InfusionRegistry` is passed to `QueryEngine::with_infusion_registry()`,
and an integration test in `crates/prism-bin/tests/` verifies that a query using a registered
`enrich` UDF resolves against a test MMDB/CSV fixture without the call being silently dropped.
(traces to BC-2.19.001 v2.1 postcondition — engine path must be wired, not unit-tested in isolation)

**AC-11 (SEC-001 / CWE-400 source file size guard):** Given an infusion spec whose source
file (CSV, JSON, or MMDB) is larger than `MAX_SOURCE_FILE_BYTES` (100 MiB),
When `InfusionLoader::load_all()` or a hot-reload event attempts to load that source file,
Then the load returns `Err` containing error code `E-INFUSE-012` with the file path and
size in bytes, the oversized file is NOT read into memory, any existing registry entry for
that infusion spec is preserved unchanged, and the error is logged at WARN level without
including any credential values.
This guard must be verified by a unit test in `prism-spec-engine/tests/infusion_tests.rs`
using a stub/temp file exceeding the limit (do not create a real 100 MiB file — use a stat
mock or a helper that reports an oversized length without allocating).
(traces to BC-2.19.001 v2.1 E-INFUSE-012 postcondition — SEC-001 hardening, CWE-400)
